# 用量与性能增强

更新日期：2026-11-04

## 已实现

- 用量页支持今天、近 7 天、近 30 天、全部保留记录、自定义日期；日期按服务器本地自然日解释。
- 按模型/别名、账号、脱敏 API Key、来源和结果交叉筛选。卡片、趋势、分组、请求明细和 CSV 使用相同筛选口径。
- 请求、Token 和缓存输入趋势切换；零值与未采集日期分别显示。宽屏利用剩余宽度，移动端表格/长图在容器内横向查看。
- 性能显示首有效 Token、总耗时、输出速度、排队时间的 P50/P95 和样本数；缺失观测显示 `—`，不是零。
- 按模型请求数、Tokens、总耗时 P95 或首 Token P95 排序；点击分组可筛选对应请求。
- 调用记录支持 25/50/100/200 条分页、成功/失败/取消筛选、请求详情和脱敏诊断复制。轮询后保留已展开详情。
- CSV 导出当前筛选的全部保留记录，而非仅当前页；保留 UTF-8 BOM、转义 CSV 单元格并处理公式前缀。
- 用量页的「重置筛选」只重置查询条件。概览中的统计重置先归档完整当前统计，再开始新的累计；归档失败时保留原数据。

## 请求与指标定义

1. **请求数**：一个客户端 completion 请求计一次。重试及模型兜底收口至同一个请求记录，实际发送次数在 `attemptCount` 中单独列示。
2. **成功率**：成功 /（成功 + 失败）。用户取消为 `cancelled`，不计入服务失败；模型探测默认与 API 请求分开。
3. **TTFT**：从 HTTP 请求进入，到第一段有效正文、推理或工具调用内容。角色帧、空工具骨架、usage 帧和心跳不计首 Token。非流式与无有效输出的请求保持 `null`。
4. **输出速度**：明确的输出 Tokens / 首有效内容到请求结束的时间。观测窗口不足 200ms 或缺输出用量时保持 `null`。
5. **排队时间**：本请求内各次 `pool.acquire()` 的实际累计等待，不把重试退避混入其中。
6. **Tokens**：仅累计已知输入/输出分量；缓存是输入的子集，不重复加到总量。`usageKnownRequests` 表示输入/输出分量完整的请求数。失败重试的已知用量只保留在尝试诊断中，未报告的消耗不估算。
7. **已知尝试**：`attemptKnownRequests` 区分「上游尝试 0 次」和「旧版未记录尝试次数」。
8. **完整回复后关闭**：客户端收到 `finish_reason` 后停止消费，若回复完整且无上游错误，仍按成功处理。
9. **分位数**：nearest-rank，只包含有效实测样本。性能模块与当前筛选一致，不将失败或取消的零值伪装成成功请求样本。

## 历史兼容

- 保留旧的累计请求数和 Token 数值，不从旧版最近 200 条明细倒推全量历史。
- 新明细保留最近 **30 个本地自然日、最多 10000 条**。旧版从 `recent` 迁移，缺失的身份、用量分量和性能不回填。
- `/admin/api/state` 不传输内部完整 history，仍只携带最多 200 条最近代理请求；探测记录通过独立查询接口查看。筛选页使用独立分页接口。
- 新增累计只纳入代理请求；模型探测、管理请求仍进入各自来源的查询明细。
- Key 使用 SHA-256 短标识及尾号展示；旧 Key 分组标识在加载时脱敏，原累计量保留。
- 历史未覆盖、记录裁剪和时间淘汰均提供覆盖说明。使用者应区分「保留明细汇总」与「历史累计」。
- 积分沿用上游账号账单，不虚构模型或 Key 的积分分摊。已有账号、模型路由、调度、背压和取消上游能力保持。

## 接口

管理接口继续要求原有管理员鉴权：

```http
GET /admin/api/usage?range=7d&source=proxy&limit=50&offset=0
GET /admin/api/usage?range=custom&from=2026-11-01&to=2026-11-04&model=MODEL&outcome=ok
GET /admin/api/usage/export.csv?range=7d&source=proxy
```

可选字段：`range`、`from`、`to`、`model`、`accountId`、`apiKeyId`、`source`、`outcome`、`limit`、`offset`。

- 来源：`proxy` / `probe` / `admin` / `all`。
- 结果：`all` / `ok` / `failed` / `cancelled`。
- `custom` 必须同时提供有效的起止日期。无效筛选返回 HTTP 400。
- CSV 忽略分页参数，导出同条件下全部保留明细，响应头标明记录数与历史覆盖状态。

## 验证方法

使用 Node.js 20+：

```powershell
node tools/run-tests.mjs --timeout=120
node tools/verify-usage-browser.mjs
```

第二条使用 Node.js 22+ 的原生 WebSocket，并需要已安装 Chromium 浏览器，也可显式指定 `--browser`。默认创建内存测试实例、独立临时浏览器目录，不访问真实上游，不修改真实配置或账号。

新增回归文件：

- `tools/test-usage-query.mjs`：迁移、数值归一化、时区/日期、组合筛选、分页、分位数、脱敏、保留上限和归档。
- `tools/test-usage-api.mjs`：接口鉴权、口径一致、分页、CSV 全量导出与公式前缀处理、页面脚本语法。
- `tools/test-usage-telemetry.mjs`：本地 mock 上游验证首内容计时、重试/fallback 单记录、取消、断流及 finish 后关闭。

运行版本的独立账号/刷新/调度改动应保留；同步前先备份源码和统计文件，并在独立暂存副本进行回归，空闲且统计落盘后再重启原实例。
